# Install new Release from repo

Install the latest stable release from `geldmacher/security` for colleagues using Cursor, Codex, or OpenCode 2.1.2. Read [the installation procedure](../../docs/installation.md) when prerequisite, first-installation, conflict, or recovery details are needed. Report the selected release, what changed, and the one next activation step.

OpenCode config (opencode.json, commands/) is shared with Workflow and Design: merge only, touch only your own entries, never write backups; uninstall removes only your own entries; rollback means installing an older GitHub release.

1. Resolve the invoking harness from explicit session context or the user's requested target. If uncertain, ask which harness to install into. The presence of several apps is not host selection. OpenCode means `@opencode/cli` 2.1.2, not the `opencode-ai` 1.x package. When an older installed copy of this skill names only Cursor and Codex, follow the selected release tag's installation guide for the host list. Other Agent Plugins clients have no supported release archive; explain this limit without writing host files.
2. Locate [the bundled installer](scripts/install-release.mjs) relative to this skill, even when it runs from an installed cache or an unrelated working directory. Check Node.js 22 or newer. No Git checkout, GitHub CLI, npm installation, or external plugin is needed for the plugin installation.
3. Download and verify once with `node <absolute-skill-directory>/scripts/install-release.mjs --host cursor --download-dir <new-temporary-directory>`, substituting `codex` for Codex or `opencode` for OpenCode. The helper creates that new directory and refuses an existing one. Preview with the same helper and `--host cursor --release-dir <downloaded-directory> --dry-run`. Both preview and installation use these exact retained release bytes. For OpenCode, the helper merges only Security's `skills` entry and installs only Security command files. It keeps the original bytes of `opencode.json` and those command files in memory only. If a write in the same run fails, it rewrites those files from that memory and does not copy them to disk. A second run that changes nothing does not write.
4. A request to install or update authorizes this plugin's normal installation. After a successful preview, run the same installer with `--release-dir` and without `--dry-run`; do not ask again for ordinary installation permission. An inspection or preview request authorizes only the download and preview. Native sandbox approvals remain applicable. Clean up only the temporary download directory created for this invocation after the result and recovery evidence are retained.
5. If the preview reports `replacement_requires_approval`, show the installed and selected versions and the reason. Only an explicit decision to replace that identified installation permits `--replace-existing`. That replacement removes the previous plugin directory and does not retain a copy. Never use that flag merely to bypass a failed run. Stop on identity, checksum, archive, path, marketplace, cache, or OpenCode command collisions; report what changed before retrying. Rollback means installing an older GitHub release. Uninstall removes only Security's OpenCode entries.
6. Report the selected release, harness, whether files changed, native installation status, and the one next activation action. `prepared` means Codex still needs its native install step; `installed` verifies the recorded on-disk/native boundary, not live skill discovery. For OpenCode, `installed` means the package, skills registration, and Security commands are on disk. A no-op does not require reloading unchanged source, but never upgrades unknown activation to verified. A failure after the plugin directory is replaced stops and reports; recover by installing an older GitHub release.

Use the helper's normal host installation path. Do not rebuild releases, publish, modify other plugins, delete caches, trust prompts, or restart apps as part of this skill. Ordinary plugin installation does not alter global guidance. Explain host-required reload, trust, enablement, or Plugins Directory actions to the user. Complete discovery verification only after observing it in the changed host or a fresh task.
